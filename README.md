# ComfyPipeline

ComfyUI（ローカル / リモート）に接続し、**LoRA ごとの量産・吟味ワークフロー**を効率化するための Web UI です。  
シーン・ポーズ・追加プロンプトなどの微細な変化を与えた画像を大量生成し、その場で比較・選別できます。単一キャラ生成に加えて、複数キャラを領域指定で同時生成する「カップルモード」、LoRA/チェックポイントを管理する「モデルマネージャー」、生成物を整理・レタッチする「ギャラリー」、GPU マシンへ処理を委譲する「リモートモード」を備え、Web サーバーとしても Electron デスクトップアプリとしても動作します。

---

## 主な用途

- 特定の LoRA に対して複数のシーン・ポーズ・構図パターンを一括キューに流し、大量生成する
- 追加プロンプトの「ランダム1行」モードで、1生成ごとに異なるタグを試しながらベストを探す
- ランダム構図モードで構図タグをシャッフルし、多彩なアングルの画像を効率よく吟味する
- 一括キュープリセットとして設定を保存しておき、次回は1クリックで同じ量産を再現する
- カップルモードで、キャラごとに異なる LoRA・プロンプト・ポーズを領域指定して複数人を同時生成する
- モデルマネージャーで Civitai から LoRA/チェックポイントを直接ダウンロード・管理する
- 非力な PC からハイスペックな GPU マシン（リモート）へ生成・後処理をオフロードする
- ギャラリーで生成画像をフォルダ単位に整理し、モザイク適用・再生成（リビジョン）・選別（リリース）を行う

## セットアップ

### 方法 A: Electron デスクトップアプリとして使う

ComfyUI 未導入の環境でも、初回起動ウィザード（`/setup`）が Python / Git / ComfyUI 本体 / CUDA 版 PyTorch / automosaic 用 venv を自動セットアップします。

```bash
git clone <このリポジトリ>
cd comfy-pipeline
pnpm install

pnpm electron:dev    # 開発時（Next.js + Electron を同時起動）
# もしくは
pnpm electron:build  # NSIS(win) / dmg(mac) / AppImage(linux) を生成
```

初回起動時に `/setup` 画面が表示され、GPU（`nvidia-smi` からドライバ→CUDA バージョンを判定）に応じた PyTorch のインストールを含め、必要なセットアップを自動で行います。完了後は「メイン画面を開く」からいつも通り利用できます。設定（ComfyUI のパス/URL、各種モデルディレクトリ、リモート URL 等）はビルド後もアプリ内の「設定」ダイアログからいつでも変更できます（`.comfy-pipeline.json` に保存）。

### 方法 B: Web サーバーとして使う（手動セットアップ）

#### 前提

- [ComfyUI](https://github.com/comfyanonymous/ComfyUI) がローカル（またはリモートマシン）で起動していること
- Node.js 18 以上、pnpm

#### ComfyUI 側の設定

プレビュー画像をリアルタイム受信するため、ComfyUI の起動オプションに以下を追加してください。

```bat
--preview-method auto
```

#### インストール

```bash
git clone <このリポジトリ>
cd comfy-pipeline
pnpm install
```

`.env.example` をコピーして `.env.local` を作成し、環境に合わせて編集します。

```bash
cp .env.example .env.local
```

```env
COMFYUI_URL=http://localhost:8188
NEXT_PUBLIC_COMFYUI_URL=http://localhost:8188

# ComfyUI の各種ディレクトリへの絶対パス
# Windows: C:/Users/yourname/ComfyUI/output
# Mac/Linux: /home/yourname/ComfyUI/output
COMFYUI_OUTPUT_DIR=C:/path/to/ComfyUI/output
COMFYUI_LORA_DIR=C:/path/to/ComfyUI/models/loras
COMFYUI_CHECKPOINT_DIR=C:/path/to/ComfyUI/models/checkpoints

# Civitai からのモデルダウンロードに使用（任意）
CIVITAI_API_KEY=
```

> `.env.example` に載っていない `COMFYUI_UPSCALER_DIR`（アップスケールモデルのディレクトリ）や `REMOTE_PROCESS_URL`（リモートモード先 URL）、`comfyuiApiKey` などは、起動後にアプリ内の「設定」ダイアログから設定することもできます。環境変数を設定した項目は設定ダイアログ側では変更不可（優先度: 環境変数 > `.comfy-pipeline.json` > デフォルト値）として表示されます。

#### 起動

```bash
pnpm dev
```

ブラウザで `http://localhost:3000` を開きます。

## 機能詳細

### LoRA 設定

可変 LoRA をリスト管理します。名前・強度・CLIP 強度・トリガーワードを設定し、生成時にリストから1つ選択して使用します。

### プロンプトビルダー

プリセットを組み合わせてポジティブプロンプトを構築します。

| カテゴリ   | 選択方式 | 用途                         |
| ---------- | -------- | ---------------------------- |
| 身体的特徴 | 複数可   | 髪色・体型など固定の外見特徴 |
| 人数       | 1択      | solo / 2girls など           |
| ポーズ     | 1択      | cowgirl position など        |
| シーン     | 1択      | 背景・場所                   |
| その他     | 複数可   | blush / embarrassed など     |

各プリセットには LoRA を紐付けることができ、そのプリセット選択時にシーン専用 LoRA を自動で適用できます。  
プリセットはドラッグ＆ドロップで並び替え可能、カテゴリ分け（追加・編集・削除は「カテゴリ管理」から）して整理できます。

#### 追加プロンプト

テキストエリアに自由記述できます。モードは2種類：

- **全行使用** — テキストエリアの内容をそのまま毎回追加
- **ランダム1行** — 1行1タグとして入力し、生成ごとにランダムで1行を選択

ランダム1行モードでは、完成画像のサムネイルにカーソルを乗せると、その画像に実際に適用されたタグをプレビューと一緒に確認できます。

### サンプラー設定

チェックポイント・アップスケールモデル・解像度・ステップ数・CFG・サンプラー・スケジューラー・denoise を設定します。

解像度はプリセットボタンから素早く選択できます：

| プリセット | サイズ      |
| ---------- | ----------- |
| 横長       | 1536 × 1136 |
| 正方形     | 1024 × 1024 |
| 4:3        | 1536 × 1152 |
| 3:4        | 1152 × 1536 |
| 縦長       | 960 × 1600  |

**アップスケール後の追加ステップ数（`upscaleSteps`）** を 0 より大きい値に設定すると、アップスケール画像に対して denoise 0.5 の追加 KSampler パス（hires-fix 的な精密化）が挿入されます（詳細は [ワークフロー構成](#ワークフロー構成) 参照）。0（デフォルト）の場合は従来通りアップスケールのみで保存されます。

### ランダム構図モード

有効にすると、各枚ごとにランダムな構図タグを1つ追加します。  
タグは1行1エントリで入力（例：`from above,` / `dutch angle,` / `close-up, upper body,`）。  
量産時に構図のバリエーションを自動で散らしたい場合に便利です。

### カップルモード（複数キャラ同時生成）

左パネルの「通常 / カップル」タブから切り替えられる、複数キャラクターを領域指定で同時生成するモードです。キャラごとに異なる LoRA・プロンプト・立ち位置を指定できます。名前付きの設定（`CoupleConfig`）を複数保存・切り替え可能です。

生成方式は2種類から選べます。

- **テキスト領域指定（`COUPLE()`構文）** — Prompt Control 系のノードでテキストベースに `COUPLE(xStart xEnd, yStart yEnd)` として矩形領域とプロンプトを指定
- **カラーマスク方式** — 領域ごとに色を割り当てたカラーマップ画像をキャンバスで描き、領域ごとに個別の LoRA（`CreateHookLora`）を適用しつつ `RegionalConditioningColorMask` でコンディショニングを合成。任意でポーズ用 ControlNet（画像 + strength/start/end）も適用可能

領域プロンプト・カラーマップ・ポーズ画像は、内蔵の「構図エディタ」（キャンバス、ペン/塗りつぶし/消しゴム、保存/読込）で作成できます。両方式とも、アップスケール精密化パスは通常モードと同様に適用されます。

### キューシステム

- **キューに追加** — 現在の設定でジョブを1件追加。「枚数」フィールドで1ジョブあたりの生成枚数を指定
- **中断** — 実行中のジョブを停止（次の pending ジョブは自動で継続）
- キューは順番に自動処理されます
- キュー投入済みアイテムは実行前にその場で編集可能（プロンプト・LoRA・設定）

### 一括キュープリセット

複数の設定パターンを「プリセットセット」として保存し、1クリックで全件キューに流す機能です。プリセットは ID で参照されるため、実行時に最新のプリセット内容（プロンプト等の編集）が自動的に反映されます。

#### 使い方

1. 左パネルで生成したい設定（シーン・ポーズ・追加プロンプトなど）を組む
2. **「一括キュー」** ボタンを開き、「新しいセットを作成」
3. 編集画面で **「現在の設定をプリセットとして追加」**（クイック追加ボタンからも可能）を繰り返し、パターンを登録する  
   （例：カジノ×カウガール、ホテル×M字開脚、アウトドア×立ちポーズ…）
4. セットを保存
5. 「実行設定」画面で可変 LoRA・物理系プリセット・シーンプリセット・生成設定（サンプラー設定等の上書き）をまとめて指定し、「実行」でキューに流す

プリセットごとに枚数・追加プロンプト・追加プロンプトモード・出力ファイル名プレフィックスを個別設定できます。  
セットはエクスポート/インポートで共有・バックアップできます。

### プレビューパネル

- 生成中はリアルタイムプレビューを常にメインビューに表示
- 生成完了した画像はストリップ（横並びサムネイル）に順番に追加
- **サムネイルにカーソルを乗せると大きなプレビューを表示**  
  ランダム1行モード使用時は適用されたタグもあわせて表示
- 生成完了後は最後の画像がメインビューに自動フォーカス  
  ストリップのサムネイルをクリックすると任意の画像をメインに切り替え可能
- 画面右下にフローティングウィンドウで ETA（残り枚数・時間）や、現在組み立てられているプロンプト内容を表示可能

### ギャラリー（`/gallery`）

生成画像をフォルダ（生成バッチ）単位で閲覧・選別・レタッチする専用ページです。

- フォルダ一覧（サムネイル・枚数・リリース済み枚数つき）→ フォルダ内の画像一覧（保存済みメタデータ: プロンプト・LoRA・設定を画像ごとに確認）
- **リリース** — 気に入った画像を `<フォルダ>_release/` へコピー（選別マーク）。解除も可能
- **削除** — 画像本体・メタデータ・サムネイルキャッシュ・リリースコピーをまとめて削除
- **再生成（リビジョン）** — 気に入らない画像を同条件で再生成し、`<元ファイル名>_rev_0001` のように連番を振って元画像と紐付けて保存
- **モザイク適用** — ギャラリーのフォルダに対して直接 automosaic を実行（`/process` と同じ処理基盤を再利用）
- リモートモード時、再生成した画像はリモートマシンから自動でダウンロードされてローカルに同期されます

### モデルマネージャー

LoRA / チェックポイント / アップスケールモデルを一覧・管理するダイアログです（ヘッダーから開く）。

- サムネイル・ファイルサイズ・更新日時つきで一覧表示、ソート・検索可能
- Civitai のモデル/バージョン URL を貼り付けるだけでモデルをダウンロード（進捗表示つき）。トリガーワードやモデル ID を含む `.civitai.json` サイドカーとプレビュー画像を自動保存
- モデルの削除（本体・サムネイル・サイドカーをまとめて削除）
- アップスケールモデルは一覧表示のみ（`ESRGAN` / `RealESRGAN` サブフォルダを走査）
- リモートモード時は、すべての操作が透過的にリモートマシンへプロキシされます

### リモートモード

非力な PC（Web UI 操作用）と、ComfyUI・automosaic を実際に実行する GPU マシンを分離して使うための機能です。「設定」ダイアログで `リモート処理サーバー URL` を指定すると、以下がそのマシン上で動く同一アプリのインスタンスへ自動的にプロキシされます。

- モデルマネージャー（LoRA/チェックポイント/アップスケーラーの一覧・ダウンロード・削除・サムネイル）
- `/process` の automosaic / リサイズ実行、CPU/GPU モニタリング、フォルダ一覧
- 生成画像・処理済みフォルダの同期（アップロード/ダウンロードは差分のみ、既存ファイルはスキップ）

なお ComfyUI 自体への生成リクエスト（`/prompt` 送信）は常に設定された `COMFYUI_URL` へ直接送信され、リモートモードの対象外です（リモートの ComfyUI を直接指定してください）。

### 設定

ヘッダーの歯車アイコンから開く設定ダイアログで、ComfyUI のパス/URL/API キー、各種モデルディレクトリ、出力ディレクトリ、リモート処理サーバー URL、Civitai API キーを変更できます。値は `.comfy-pipeline.json` に保存され、環境変数が設定されている項目は環境変数が優先されます（Electron ビルドではビルド後に環境変数を変更できないため、この仕組みが必須です）。

### エクスポート / インポート

ヘッダーのボタンから設定を JSON ファイルとして出力・読み込みできます。  
以下の内容が含まれます：

- 可変 LoRA リスト
- 全プリセット（身体・人数・ポーズ・シーン・その他、カテゴリ含む）
- サンプラー設定
- ネガティブプロンプト
- ランダム構図タグ
- 一括キュープリセットセット

## ワークフロー構成

ComfyUI に送信するワークフローは基本的に以下の構成です（通常モード）：

```
CheckpointLoaderSimple
  └─ LoraLoader × N  (FIXED_LORAS → プリセットLoRA → 可変LoRA の順)
       ├─ CLIPTextEncode (ポジティブ)
       ├─ CLIPTextEncode (ネガティブ)
       └─ KSampler
            └─ VAEDecode
                 └─ ImageUpscaleWithModel
                      └─ SaveImage（upscaleSteps = 0 の場合はここで完了）
```

**アップスケール精密化パス**（`upscaleSteps > 0` の場合）を有効にすると、アップスケール後にさらに以下が追加されます：

```
                      └─ ImageUpscaleWithModel
                           └─ VAEEncode（アップスケール画像を再エンコード）
                                └─ KSampler（新しいシード, steps=upscaleSteps, denoise=0.5）
                                     └─ VAEDecode
                                          └─ SaveImage
```

固定 LoRA（`FIXED_LORAS`）は常にチェーンの先頭に適用されます。  
カスタマイズする場合は [lib/comfy.ts](lib/comfy.ts) の `buildWorkflow` / `FIXED_LORAS` を編集してください。

カップルモードでは代わりに [lib/couple.ts](lib/couple.ts) の `buildCoupleWorkflow`（`COUPLE()` テキスト領域指定 + Prompt Control）または `buildColorMaskWorkflow`（カラーマスク + `RegionalConditioningColorMask` + 任意で ControlNet）が使われ、領域ごとに異なる LoRA・プロンプトを合成しますが、アップスケール精密化パスは通常モードと共通で適用されます。

## automosaic — 自動モザイクツール

画像内の性器等を YOLOv8 モデルで自動検出してモザイクをかけるツール。実体は `automosaic/automosaic.py` / `automosaic/resize.py`（Web UI・セットアップウィザードから利用されるのはこちら）。  
リポジトリ直下の `automosaic_example/` は改変前のオリジナルスクリプトをそのまま置いた参照用コピーで、実行には使用されません。  
元スクリプト: [よくある質問 - sd_toshiaki Wiki](https://wikiwiki.jp/sd_toshiaki/%E3%82%88%E3%81%8F%E3%81%82%E3%82%8B%E8%B3%AA%E5%95%8F)

### 動作環境

- Windows + Python（PATH 通り済み）
- CUDA 対応 GPU 推奨（なければ CPU でも動作）
- 空き容量 6GB 以上

### セットアップ

Electron 版・セットアップウィザードを使う場合は自動でインストールされます（[初回セットアップウィザード](#初回セットアップウィザードsetup)参照）。手動で使う場合は以下の手順です。

#### 1. 初回起動（venv 作成 + 依存インストール）

`automosaic` ディレクトリで `automosaic.bat` をダブルクリックするか、画像ファイルをドロップします。  
初回は自動で venv が作成され pip インストールが走ります（数分かかります）。

```
[ERROR]処理対象の画像ファイルが見つかりませんでした
```

が表示されればインストール完了です。

#### 2. 検出モデルの配置

`automosaic/models/` フォルダにモデルファイルを配置します。

| 対象   | ファイル名   | 入手先                                                                                                                        |
| ------ | ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 女性器 | `pussyV2.pt` | 自動ダウンロード（HuggingFace）、または [CivitAI](https://civitai.com/models/132388?modelVersionId=149617)                    |
| 男性器 | `penis.pt`   | [ntd11 モデル（CivitAI）](https://civitai.red/models/1313556?modelVersionId=2350456) からダウンロードし `penis.pt` にリネーム |
| 顔など | 任意の `.pt` | 別途 YOLOv8 セグメンテーションモデルを取得して `models/` に配置                                                               |

### 使い方

#### コマンドラインから

| 操作                                          | 説明                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| `automosaic.bat` をダブルクリック             | `input/` フォルダ内の画像を処理 → `output/` に出力（実行後に一時停止） |
| 画像 / フォルダを `automosaic.bat` にドロップ | 指定ファイルを処理 → `output/` に出力                                  |
| 画像を `automosaic_quick.bat` にドロップ      | 元画像と**同じフォルダ**に出力（プロンプト非表示）                     |

処理後のファイル名には `_mosaic` が付加されます。検出がなかった場合もファイルはそのままコピーして出力されます。

#### Web UI から使う（推奨）

`pnpm dev`（または Electron 版アプリ）で起動後、ヘッダーの **「画像処理」** リンク（`/process`）から GUI で操作できます。ローカルフォルダに加え、リモートモード設定時はリモートマシンのフォルダへアップロード → 処理 → 結果を同期（差分のみダウンロード）する運用も可能です。またギャラリー画面（`/gallery`）からも、フォルダ単位で直接モザイク適用を実行できます。

```
┌─────────────────────────────────┬───────────────────────────────────┐
│  左パネル（設定）                │  右パネル（モニタリング）          │
│  - 処理対象フォルダ選択          │  システムリソース（常時表示）       │
│    (ローカル / リモート)         │    CPU% / GPU% / VRAM 折れ線グラフ │
│  - 自動モザイク設定              │    2秒ごと自動更新（直近 80s）     │
│    モデル・クラス選択            ├───────────────────────────────────┤
│    信頼度 / モザイクサイズ       │  ジョブ進捗                        │
│    検知範囲拡張                  │    進捗バー・枚数カウント          │
│  - リサイズ / 圧縮設定           │    ETA（経過 / 残り / 枚/秒）      │
│    合計サイズ自動計算            │    処理ログ                        │
│  - 処理開始ボタン                │    同期（リモート時）/ ZIP ダウンロード │
│                                 │  処理前後ギャラリー                │
└─────────────────────────────────┴───────────────────────────────────┘
```

- **GPU グラフ**: NVIDIA GPU がある場合は GPU 使用率・VRAM も表示（`nvidia-smi` が PATH に必要）。リモートモード時はリモートマシンの値を表示
- **ETA**: 2 枚以上処理されると処理速度（枚/秒）から残り時間を自動計算
- **処理順序**: リサイズ → モザイクの順で実行。大きな画像を先に縮小することで PNG 保存の I/O ボトルネックを解消

### オリジナル `automosaic.py` からの改善点

元スクリプトは動作・機能面でそのまま継承しつつ、以下を改善しています。

#### パフォーマンス

| 項目             | オリジナル                                     | 改善後                                                                                                                    |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| モデルのロード   | 画像 1 枚ごとに毎回 `YOLO(path)` を呼び出す    | スレッドごとに初回のみロード（thread-local キャッシュ）                                                                   |
| 並列処理         | シングルスレッド逐次処理                       | `ThreadPoolExecutor` で並列処理（`-w` オプション）。PyTorch/CUDA は GIL を解放するためスレッド並列が有効                  |
| 検出前リサイズ   | 常にフルサイズで YOLO 推論                     | `--detect-size` で長辺を指定サイズに縮小してから推論。bbox / マスクは元サイズへスケールバックするので出力品質は変わらない |
| モザイク補間     | 縮小に `BICUBIC`（過平滑、モザイクらしくない） | 縮小に `BOX`（ダウンサンプリングに適した平均化補間）                                                                      |
| 処理時間の可視化 | なし                                           | `[検出] X.XXX秒 / [加工] X.XXX秒 / [保存] X.XXX秒` を各画像ごとに出力                                                     |

#### 機能追加

| オプション        | 説明                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------- |
| `-w / --workers`  | 並列処理スレッド数（デフォルト: 1）。CUDA 環境では 2〜4 が目安                        |
| `--detect-size N` | 検出前に長辺を N px に縮小（例: `--detect-size 1024`）。大きな画像で推論を高速化      |
| `--classes`       | 検出クラスをカンマ区切りで絞り込み（`nipples,pussy,penis` 等）。元は全クラス固定      |
| `-e / --expand`   | 検知範囲を bbox サイズの指定割合で拡張。マスクも `MaxFilter` で同量拡張（元にはなし） |

#### 動作変更

| 項目                     | オリジナル                               | 改善後                                                  |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------- |
| 検出なし時の出力         | ファイルを出力しない                     | オリジナルをそのままコピーして `_mosaic` ファイルを出力 |
| bbox の w/h チェック     | なし（ゼロサイズ bbox でエラーの可能性） | `w <= 0 or h <= 0` の場合スキップ                       |
| `combined_bboxes` 初期化 | `None` で初期化し `+= result.bboxes`     | 最初から空リストで `+=`（None チェック不要）            |

### リサイズ処理 (`resize.py`) の仕様

アスペクト比を保ったまま画像をリサイズし、メタデータ（Exif / PNG チャンク）を保持して保存するツール。

#### 基本仕様

| 項目              | 仕様                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| 対応フォーマット  | JPEG / PNG / WebP / AVIF / BMP                                       |
| アスペクト比      | 保持（`LANCZOS` でリサンプリング）                                   |
| メタデータ        | JPEG / WebP / AVIF は Exif コピー、PNG は itxt チャンクコピー        |
| WebP ロスレス判定 | `VP8L` チャンクを検出して自動判定、ロスレスは `lossless=True` で保存 |
| スケール指定      | `0.01〜1.0`（例: `50` → 50%）                                        |
| 品質指定          | JPEG / WebP / AVIF の品質を 1〜100 で指定（PNG は無視）              |

#### 並列処理

- `-w / --workers` でスレッド数を指定（**デフォルト: CPU コア数**）
- PIL の `resize()` / `save()` は GIL を解放するため、スレッド並列が素直に効く
- PNG 圧縮は CPU バウンドなのでコア数に比例してスケール
- ディレクトリ作成の競合防止に `threading.Lock` を使用

#### Web UI での処理順序

```
入力フォルダ
    │
    ▼ (1) resize.py  ─ CPUコア数スレッドで並列リサイズ
_resize_tmp/ （中間ファイル）
    │
    ▼ (2) automosaic.py  ─ 縮小済み画像に YOLO 検出 + モザイク適用
{folder}/mosaic/  （最終出力）
    │
    ▼ _resize_tmp/ を自動削除
```

リサイズを先に行うことで、モザイク処理での **YOLO 前処理・モザイク適用・PNG 保存すべてが小さい画像で完結** します。元画像が 6400px の場合、50% リサイズ後は 3200px となり PNG 保存時間が数倍〜十倍程度改善します。

#### コマンドラインオプション

```
python resize.py <input_dir> [options]

-o DIR          出力フォルダ（デフォルト: output）
-s SCALE        リサイズ率 %（デフォルト: 50）
-q QUALITY      品質 1-100（JPEG/WebP/AVIF のみ、デフォルト: 85）
-w WORKERS      並列スレッド数（デフォルト: CPU コア数）
```

### automosaic コマンドラインオプション一覧

```
python automosaic.py [target ...] [options]

-m MODELS          使用モデルをカンマ区切りで指定（デフォルト: pussyV2.pt,penis.pt）
                   女性器のみ: -m pussyV2.pt
-o DIR             出力先フォルダを指定
-ssd               入力画像と同じフォルダに出力（automosaic_quick.bat はこれを使用）
-s SIZE            モザイクサイズ（デフォルト: 10、大きいほど粗い）
-c 0.25            信頼度しきい値（小さいほど広く検出、誤検知も増える）
-w N               並列処理スレッド数（デフォルト: 1）。CUDA 環境では 2〜4 が目安
--detect-size N    検出前に長辺を N px に縮小して推論、結果は元サイズにスケールバック
--classes CLASSES  検出クラスをカンマ区切りで指定（例: nipples,pussy,penis）
-e RATIO           検知範囲を bbox サイズの RATIO 倍拡張（例: 0.1 = 10% 拡張）
-rm                高解像度セグメンテーションマスクを使用
-sp                検出枠つきプレビュー画像を追加出力
-sm                マスク画像を追加出力
-n, --no-meta      メタデータのコピーを無効化（問題発生時に試す）
-d DEVICE          処理デバイス（CPU 指定: -d cpu）
```
