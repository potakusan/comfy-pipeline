# コンポーネント（`components/`）の規約

## ディレクトリ構成

`components/`直下は機能ドメイン別のサブフォルダで構成する。`components/ui/`のみshadcn/uiのプリミティブ専用で、新規コンポーネントを置かない。

- `common/`: 3ドメイン以上、またはヘッダー経由で全ページから使われる共有コンポーネント（例: `app-header.tsx`, `tag-autocomplete-textarea.tsx`, `delete-confirm-dialog.tsx`）
- `models/`: モデル管理ダイアログ一式
- `settings/`: 設定ダイアログ
- `gallery/`: `/gallery`ページ専用のコンポーネント群
- `pipeline/`: `app/_home.tsx`（生成パイプライン画面）が組み立てるコンポーネント群
  - `lora/`, `prompt/`, `couple/`, `queue/`: それぞれ独自の衛星ファイル群（サブコンポーネント・型・純粋関数）を持つクラスタはサブフォルダにまとめる
  - 衛星ファイルを持たないリーフコンポーネントは`pipeline/`直下に置く（例: `preview-panel.tsx`, `sampler-settings.tsx`）
- 新しいコンポーネントは、どのページ・ドメインから使われるかを基準に上記のいずれかへ配置する。判断に迷ったら実際の利用箇所（import元）を`grep`で確認する
- ファイル名はkebab-case（`camelCase`や`PascalCase`にしない）
- あるコンポーネントの内部でのみ使う分割ファイル（読みやすさのためのprivateなセクション分割）は、同じサブフォルダ内に置いてよい。無理にネストを増やす必要は無い
- 2つ以上のコンポーネントで見た目や構造が重複したら、共有プレゼンテーション用コンポーネントとして両者の最も近い共通ドメインフォルダ（3ドメイン以上にまたがる場合は`common/`）に切り出し、差分だけを`children`/propsで渡す

## Props設計

- 1つのコンポーネントが複数の独立した機能領域(タブ、セクション等)を扱う場合、フラットなpropsを並べるのではなく機能単位でオブジェクトにグルーピングする。目安として1コンポーネントのpropsが10個を超えたらグルーピングを検討する
- グルーピングだけでは結合度は下がらない。グルーピング後もleaf数が多いなら、JSX上独立したセクションごとにコンポーネント分割を優先する
