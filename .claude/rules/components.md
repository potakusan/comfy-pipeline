# コンポーネント（`components/`）の規約

## ディレクトリ構成

`components/`直下はフラット構成（機能単位のサブフォルダは無い）。`components/ui/`のみshadcn/uiのプリミティブ専用で、新規コンポーネントを置かない。

- 新しいコンポーネントは基本的に`components/`直下に1ファイルとして追加する（例: `gallery-panel.tsx`, `queue-manager.tsx`）。フォルダ単位で管理する規約は無い
- ファイル名はkebab-case（`camelCase`や`PascalCase`にしない）
- あるコンポーネントの内部でのみ使う分割ファイル（読みやすさのためのprivateなセクション分割）も同じフラット構成で`components/`直下に置いてよい。フォルダ化して隠す必要は無い
- 2つ以上のコンポーネントで見た目や構造が重複したら、共有プレゼンテーション用コンポーネントとして`components/`直下に切り出し、差分だけを`children`/propsで渡す

## Props設計

- 1つのコンポーネントが複数の独立した機能領域(タブ、セクション等)を扱う場合、フラットなpropsを並べるのではなく機能単位でオブジェクトにグルーピングする。目安として1コンポーネントのpropsが10個を超えたらグルーピングを検討する
- グルーピングだけでは結合度は下がらない。グルーピング後もleaf数が多いなら、JSX上独立したセクションごとにコンポーネント分割を優先する
