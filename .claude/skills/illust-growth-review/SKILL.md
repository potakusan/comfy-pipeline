comfy-pipelineで量産してPixivに投稿したイラストの成長分析・KPIレビューを行う。
**数値計算は `analyze.js` に一任し、このスキルは「実行→過去レビューとの比較→
文章化→review/への保存」を担当する**（分析ロジックを都度その場で書き直さない。
毎回同じ手法で計算することで回を跨いだ比較が意味を持つ）。

## 前提

- 入力: `data/illust.json`（Pixiv自作品一覧APIの生レスポンス。無ければユーザーに
  配置を依頼して停止する）
- 出力: `review/YYYY-MM-DD-growth-review.md`
- `data/` と `review/` は `.gitignore` 済み（個人のPixiv実績データのため）

## 進め方

1. **`data/illust.json` の存在確認**。無ければ配置を依頼して終了する
2. **`analyze.js` を実行**して構造化メトリクスを取得する

   ```bash
   node .claude/skills/illust-growth-review/analyze.js
   ```

   目標日を年末以外にしたい場合(ユーザー指定があれば)は `--target=YYYY-MM-DD` を付ける。
   省略時は「今年の12/31」（すでに過ぎていれば来年の12/31）がデフォルト

3. **過去レビューとの比較**: `review/` 配下の既存mdのうち直近1件を読み、
   末尾のJSONブロック（後述のフォーマット）から前回の主要数値
   (`postsPerDay`, `growthCurve.*.plateau`, `projection.scenarios.*`) を取り出し、
   今回との差分を算出する。過去レビューが無い場合(初回実行)は比較セクションを省略する
4. **レポート作成**: 下記テンプレートに従い `review/<今日の日付>-growth-review.md`
   を新規作成する。単なる数値の書き写しではなく、「何が変わったか・なぜそう
   読めるか」を一言添える（例: 成熟度調整で見かけの落ち込みが解消する/しない、
   プラトー値が前回から動いたか等）
5. ユーザーに保存先パスと要点(投稿ペース・プラトー値・KPI予測)を簡潔に報告する

## レポートテンプレート (`review/YYYY-MM-DD-growth-review.md`)

```markdown
# イラスト量産・投稿 成長レビュー (YYYY-MM-DD)

## サマリー

- 総投稿数: N件（YYYY-MM-DD 〜 YYYY-MM-DD、N日間）
- 直近投稿ペース: 7日/14日/30日/60日/90日/全期間平均 の日次投稿数
- 1投稿あたり枚数: 平均/中央値、複数ページ率
- 累計ブックマーク/view、ブックマーク率
- (前回レビューがあれば) 前回からの変化を1〜2行で

## 成長曲線(年齢別プラトー・ランプ比率)

投稿からの経過日数ごとにブックマーク/viewがどう伸びるかの表。プラトー到達までの
日数、プラトー値を明記。「ロングテールでずっと伸びる」のか「初期数週間で決まる」
のかをここで判断する

## 月次コホート比較(生値 vs 成熟度調整後)

直近数ヶ月がまだ未成熟(投稿から日が浅い)場合、生の中央値だけを見ると実力を
過小評価しがちなので、必ず成熟度調整後の値も並べて解釈する

## 目標日(YYYY-MM-DD)までのKPI予測

保守/中央/強気の3シナリオ（前提となる投稿ペースを明記）で、目標日時点の
累計作品数・累計ブックマーク・累計viewを提示

## ハイライト

ブックマーク上位5作品

## 所感・次のアクション

このレビューから読み取れる伸びしろ・懸念点、次回レビューまでに試すと良さそうな
こと（投稿頻度・タグ・投稿時間帯など）を書く。断定はせず仮説として書く

---
<!-- machine-readable: 次回レビュー実行時にこのブロックをそのまま比較対象として読む -->
\`\`\`json
{analyze.jsの出力をそのまま貼る}
\`\`\`
```

## 注意

- `analyze.js` はプラトー算出に十分なサンプル(成熟済み作品30〜250日 20件以上)が
  無いとKPI予測をスキップする(`projection.note` が入る)。その場合は無理に予測を
  作らず「データが増えたら次回以降で算出」と正直に書く
- ページ数は `body.thumbnails.illust[].pageCount` から取得している。将来Pixiv側の
  レスポンス形式が変わりこの経路が無くなった場合、`analyze.js` はページ数系メトリクスを
  nullにして残りの分析は継続する（クラッシュしない設計）
- 目標日予測はあくまで「現在の投稿ペース・1投稿あたり実力値が今後も続く」という
  単純な外挿であり、フォロワー増加による質的な伸びや、逆に量産ペースが崩れる
  リスク(過去に実際に月間投稿数が一桁まで落ち込んだ月がある)は考慮していない。
  レポートの所感でこの前提を明記する
